## 1. Amendments
- **A1 ACCEPT.** For F3, the literal rule measures about 0 on both arms. The longest per-thread ack gap ending after the fault is the right number for F3 and is neutral. Keep the literal rule for F1, F2a and F2b.
- **A2 ACCEPT WITH CHANGE: freeze 20 / 4 / 8.** Keep 20 / 1 / 3 only as a labelled line (steady cell + F1).
  - 20 / 1 / 3 is a validator floor, not a production setting. A 3 s retry_timeout on etcd backed by WSL2 invites self-demotions, and those count against the arm.
  - It also buys nothing. After a node death, the leader lease expires at the last refresh + ttl. The expected detection is about ttl − loop_wait/2: about 18 s at loop_wait 4, about 19.5 s at loop_wait 1.
  - The "lowest validator-accepted" rule is not real parity anyway. MongoDB's 5000 / 1000 is a common aggressive production tuning, not its floor. The parity rule should be "the most aggressive documented, supported setting" on both arms. For Patroni that is ttl at its floor of 20, with `loop_wait + 2 × retry_timeout = ttl`, which gives 20 / 4 / 8, the value the PREREG and both advocates predicted with.
- **A3 ACCEPT.** This holds only if the PostgreSQL gate is judged per variant (§4).
- **A4 ACCEPT** (a), (b) and (c).
- **A5 ACCEPT WITH CHANGE.** Two corrections:
  - Drop `outbox-growth-alarm`. The outbox *is* the proof table (`client/lab02_client.py:708-710`), so nothing grows beyond the data.
  - Count `idempotency-key` on both arms or on neither. Both arms rely on the client-chosen unique id, and the shared loop treats a duplicate on a retry as an ack on both (`retry.py:217-219`).
  - Result: MongoDB 4–5 against PostgreSQL + outbox 8–9. The verdict does not change.
- **A6 ACCEPT.** F1b is labelled, and Patroni plays the same supervisor role.
- **A7 ACCEPT WITH CHANGE.**
  - Combined cells are fine: the decoding load at 20 writes/s is negligible.
  - The redundancy wait must also require, on every replica:
    - `lab02_perm` present;
    - Patroni `pending_restart` false;
    - `synchronous_standby_names` listing both standbys.
  - Otherwise the next fault can land while a replica restarts to install the copied slot (see V2).
  - Add one labelled block to bound the overhead: outbox only, `wal_level=replica`, no slots, F1 at both cells, 5 repetitions on seed 1.
- **A8 ACCEPT WITH CHANGE: make the PostgreSQL number exact.**
  - Before the heal in F2a and F2b, `docker exec psql` into the old primary and read this cell's ids. It is now a read-only standby that cannot reach the leader, so it has not rewound yet.
  - Ids present there but absent at the end are exactly the accepted-never-acked ones, as exact as MongoDB's rollback files.
- **A9 ACCEPT.**
- **A10 ACCEPT.** HAProxy is a single point of failure on one host, not PostgreSQL's best design.
- **A11 ACCEPT WITH CHANGE (fairness to MongoDB).**
  - Taking the best of two variants in every repetition is a min of two noisy samples, and it biases the result toward PostgreSQL.
  - Instead, pick one variant per (timing cell, fault): among the variants passing every cell, the lowest median of the repetition medians on seed 1. Use that variant for all pairs on both seeds.
  - Still publish the per-repetition best.
- **A12 ACCEPT.**
  - R4 is a correctness requirement, not a handicap. Without it, a retry against a cut-off old primary acks a row that exists only locally, and that row is lost on rewind.
  - Its cost is one extra round trip per write, irrelevant to the outage metric. Optionally fold it into the INSERT statement.

No objections to R1–R12. R12's keepalives with `tcp_user_timeout` 5 s detect a dead peer in about 5–6 s, on par with `timeoutMS` 5 s.

## 3. Vetoes
- **V1: the tuned cell at 20 / 1 / 3 (A2).**
  - Why: it is an unrealistic configuration whose only effects are more false-demotion risk and no gain.
  - Fix: freeze 20 / 4 / 8.
- **V2: the redundancy check does not cover PostgreSQL's rejoin state** (`lab02lib/observe.py:43-56`).
  - Why: "streaming and lag ≤ 1 MiB" can be true while the quorum set is not yet restored, the permanent slot is missing, or a replica restart is pending. A fault in that window is a strawman of "full redundancy".
  - Fix: add the three A7 conditions to `redundant()` for PostgreSQL, and count that time in time-to-redundancy.

Not vetoes, but please record and publish:
- **The etcd leader at each fault.** When the killed node also leads etcd, the new etcd leader renews every lease. Detection then becomes about ttl + 1 s instead of about ttl − loop_wait/2. This is real behaviour of a co-located etcd and should stay, but publish the split.
- **The libpq dead-host cost.** Each reconnect pays `connect_timeout` 2 s on the dead host when it is listed before the new primary. This is genuine libpq behaviour; it shows up in the rediscovery split.
- **Fairness to MongoDB: a possible single-copy window.** With `synchronous_mode_strict: false`, Patroni may disable synchronous replication on a newly promoted primary until the third node reattaches. Writes acknowledged in that window have one copy, which is weaker than `w: majority`.
  - Check this in the smoke cells (the new primary's `synchronous_standby_names` in its first seconds), and log acks made while it was empty.
  - If any appear, the compared variant should be strict mode. In a 3-node cluster, strict ANY 1 has the same durability as majority and never blocks while one standby is alive.

## 4. Code against the PREREG and the protocol
- **`lab02lib/verdict.py:29-36, 58-59`.** PostgreSQL "passes the gate" when each repetition has *some* passing variant, so quorum could fail one repetition and classic another, and PostgreSQL would still pass. This contradicts the module's own docstring (line 7) and the PREREG's "best passing variant". Fix: a variant passes only if all its cells on both seeds pass; select only among those.
- **`lab02lib/components.py:82`.** `outbox-growth-alarm` is counted although no separate outbox table exists (`client/lab02_client.py:708-710`).
- **`lab02lib/components.py:74`.** The idempotency key is counted on PostgreSQL only, although the mechanism is the same on both arms (`retry.py:217-219`).
- **`client/lab02_client.py:282`.** Every `OperationalError` is marked ambiguous, including connection failures where nothing was sent. This only affects the diagnostic counts; the readback resolves them. Mark connect-phase failures as not ambiguous.
- **`lab02lib/observe.py:43-56`.** See V2.
