# MongoDB advocate review of the Lab 02 runner protocol (A1–A12, R1–R12)

Reviewer: an independent model reviewer (Claude, fresh context), briefed to give MongoDB its best realistic HA design and to veto strawmen. Done 2026-10-25, read-only, against PREREG v1, FREEZE-NOTES, PROTOCOL-LAB02.md and the runner code at private commit `66a6e072`. Published verbatim (the v1.1 round).

## 1. Proposed amendments
- **A1, ACCEPT WITH CHANGE.** The literal rule is biased against MongoDB in F3. `replSetStepDown` blocks writes as soon as it runs. Patroni's old primary keeps acknowledging writes through the pre-demote checkpoint. On top of that, the `docker exec … python` start-up delay lets both arms acknowledge writes after t_fault. The literal number therefore measures start-up and demotion order, not the switchover.
  - Change: for F3 only, the compared number is the median over the 8 threads of the longest ack gap that ends in (t_fault, hold end]. Bound `ack_gaps` to that window.
  - Publish the literal number as well.
  - F1 and F2 keep the literal rule.
- **A2, ACCEPT.** The literal rule ("the lowest values the pinned validator accepts", 20 / 1 / 3) is the frozen text. MongoDB's tuned cell stays at its frozen 5000 / 1000. This is conditional on veto V3, because the aggressive Patroni values must carry their false-failover risk.
- **A3, ACCEPT.** It is symmetric. Label the verdict "gate-only".
- **A4, ACCEPT (a), (b) and (c).**
  - On (a): a literal disjunction ("or ≥ 2 fewer kinds" inside every fault verdict) would let the component count decide every fault scenario. That would be unfair to PostgreSQL, and it contradicts every frozen prediction.
- **A5, ACCEPT WITH CHANGE.** MongoDB 4 against PostgreSQL 10 is right in substance. The retention alarm must be charged symmetrically.
  - MongoDB pays for an oplog-window alarm because rejoin depends on the window.
  - PostgreSQL runs `use_slots: true` (`pg-node/patroni.yml:31`) with `max_slot_wal_keep_size` unset. That carries the mirror risk: WAL piles up behind a dead member's slot, or the slot is dropped and the member needs a reinit.
  - Change: either add "physical-slot WAL-retention alarm" to `PG_COMMON`, or drop MongoDB's oplog-window alarm. Either way the verdict does not change.
- **A6, ACCEPT.** A 1 s restart loop is the systemd equivalent. The PostgreSQL arm's supervisor (Patroni) is already counted. F1b stays labelled.
- **A7, ACCEPT.** This is PostgreSQL's call. Running three consumers and `wal_level=logical` can only add load to the PostgreSQL arm.
- **A8, ACCEPT WITH CHANGE.** Never put PostgreSQL's lower bound next to MongoDB's exact rollback count as like-for-like. Tables show both arms' `unacked_absent` upper bound in the same column.
- **A9, ACCEPT.**
- **A10, ACCEPT.**
- **A11, REJECT (veto V1).** Taking the minimum of two variants per repetition is a best-of-two order statistic. It shortens PostgreSQL's number even when the two variants are identical. The PREREG says "the other arm's best passing **variant**", which is one variant.
  - Alternative: per (timing, fault), pick one PostgreSQL variant: among those passing the gate in all 10 cells, the lowest median-of-5 seed-1 outage.
  - Use that variant for all 5 pairs and for the seed-2 reproduction.
  - Apply the same rule to the feed: one feed variant must pass in every cell of the scenario, not a per-cell `best_feed`.
- **A12, ACCEPT.** R3 and R4 are correct and equally strict.
  - On MongoDB, a duplicate on a partitioned primary waits for majority on the system's last optime, so it surfaces as a write-concern error or a timeout, never as a false ack.

## 2. Runner decisions I object to
- **R9.** The "caught up" thresholds are not equivalent. 1 MiB at about 40 KB/s is about 25 s of writes on PostgreSQL, against 1 s of optime on MongoDB. That makes MongoDB's reported "time to full redundancy" stricter.
  - Change: use time on both arms, lag ≤ 1 s. PostgreSQL would use `pg_stat_replication.replay_lag` from the leader.
  - Fallback: if bytes stay, give MongoDB the time equivalent at the measured WAL rate.
- **R6.** One `MongoClient` per process must also apply to the change stream consumer (see veto V2).

## 3. Vetoes
- **V1, the per-repetition variant choice (A11).** It is a statistical tilt against MongoDB. Fix as in A11.
- **V2, the change stream consumer.** `mongo_consume` builds a new `MongoClient` on every resume and never closes it (`client/lab02_client.py:520`).
  - Every resume pays a fresh topology discovery, which inflates feed resume.
  - The monitor threads also leak in a 1 GB container during an outage.
  - A realistic application keeps one client and re-opens `watch(start_after=token)`.
  - Fix: create the client once per consumer process, and close it on exit.
- **V3, false failovers are not in any verdict.** FREEZE-NOTES M4 says false failovers "count against the arm that has them", and the tuned-cell parity was frozen on that premise. Neither `verdict.py` nor `lab02_verdict.py` reads the steady cells.
  - Fix (symmetric): if an arm has ≥ 1 false failover in a steady cell at a timing, that arm cannot get `-fits` at that timing; its lines downgrade to `both-fit`, flagged "unstable".
  - Steady-cell gate failures fail that arm's gate at that timing.
- **V4, F3 under the literal rule (A1).** It is a strawman of MongoDB's write-blocking step-down. Fix as in A1.

No veto on the other points in my brief:
- **Driver and write concern:** `w: "majority", j: true` explicit, seed list, retries on, CSOT 5 s.
- **Election settings:** reconfig touches only `electionTimeoutMillis` / `heartbeatIntervalMillis`; `catchUpTimeoutMillis` -1 and election handoff stay at their defaults.
- **Rollback accounting:** taken from every member's `rollback/`.
- **The F1b supervisor.**

## 4. Code against the PREREG and the protocol
- **`lab02lib/verdict.py:43-84`, `lab02_verdict.py`.** Steady cells and false failovers are ignored. This contradicts FREEZE-NOTES M4 and the `observe.py:82` docstring.
- **`lab02lib/verdict.py:29-36` and `lab02lib/measures.py:151-157`.** The best variant is chosen per repetition and per cell (V1).
- **`client/lab02_client.py:520`.** A new client per resume (V2).
- **`client/lab02_client.py:201-202`.** `NotPrimaryError` is classified as not ambiguous. It includes `InterruptedDueToReplStateChange` (11602) and `ShutdownInProgress` (91), which can kill a write after it was applied locally. Mark it ambiguous.
  - This affects reporting only: the gate uses acked minus present.
- **`compose-mongo.yml:70`.** Under CSOT, server selection is capped by the remaining `timeoutMS`. The effective selection wait is therefore 5 s, not the 30 s the PREREG states. This is harmless, because the application loop retries, but the manifest should record it.
- **`lab02lib/measures.py:69-82`.** `ack_gaps` has no upper bound. It needs one if A1 is adopted.
- **`observe.py:43` and `pg_sample`.** The R9 asymmetry.
